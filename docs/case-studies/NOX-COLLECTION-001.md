# Case Study · NOX Collection No.001

## 定位

「墮落與飛升」是可運作的技術原型與失敗資料庫，不是 production template。原始 repo 的 2026-07-29 postmortem 是此案最有價值的成果。

## 已證明可行

- GLB 載入、錯誤回退與公開部署。
- 捲動進度驅動六章的基本骨架。
- 自適應 DPR 與裝置分級概念。
- 單一雕塑展示的 pointer parallax、燈光與載入狀態。

## 未達標原因

1. 沒有先拆參考鏡頭與建立 Art Bible。
2. 素材層級不足，以程序化牆面／方塊替代完整場景。
3. 先做長路徑再貼六章文字，事件密度與鏡頭目的不足。
4. 為了效能過早降低清晰度，沒有先處理模型、貼圖、材質與 draw calls。
5. 單一大型場景提高後續調鏡、燈光、章節與載入的成本。
6. 正式網址、本機與 commit 缺少固定驗收證據。

## v2 可轉移規則

- 下一次只做 15–20 秒：入口、揭露、近景、一次過場。
- 每 5–10 秒至少出現一個有敘事目的的視覺事件。
- 每章先有專屬 frame、資產與光色，再談捲動長度。
- 優化順序是資產與場景結構 → post-processing → DPR，不用膜感掩飾。
- 同時保存 source、build、commit、固定座標截圖與真機結果。

## 何時才可重新開發

只有在新的 Vertical Slice Spec、資產授權、鏡頭表與 performance budget 都填完後，才從此案例抽取已驗證的片段；不得直接 fork 舊成品繼續加章節。
