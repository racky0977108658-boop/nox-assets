## 固定工作原則
以實際成品達到使用者參考品質為目標。模型可載入、程式通過、Skill 已讀取，都不代表視覺達標。每次主題與風格依需求重新定義，不照搬上一案。

## 工具與 Skill 的分工
- MCP／工具提供操作、場景資訊、渲染與截圖能力；可用能力必須實測，不能因已連線就假設能看見畫面。
- Skill 提供工作流程、專業方法、檢查標準與修正順序；Skill 本身不會自動授予視覺能力。
- 必須真正打開並檢視圖片。截圖檔案存在、日誌正常、文字場景描述，都不能代替看圖。
- 安裝、讀取、執行、驗證是四種不同狀態，回報不得混用。

## 最小有效迭代
1. 保存已接受版本、失敗版本與參考圖；鎖定一間房或一段關鍵鏡頭，先不擴張整棟。
2. 檢查工具是否能取得「最終呈現環境」的可見畫面，盡早發現 WebGL／GPU／截圖阻礙。
3. 定義構圖、光影、材質、尺度、空間深度與手機操作的具體驗收條件。
4. 按相關 Skill 完成局部實作，輸出 Blender 檢查圖。
5. 匯入真正的網頁渲染器，再看桌機與手機尺寸的畫面；固定版本、相機、時間及日夜設定，便於前後比較。
6. 每輪記錄最大的一至三個差距，集中修改再截圖。先判斷是否為模型、材質、燈光、鏡頭或匯出交接問題，避免盲調。
7. 達標才擴張；遇到同類問題反覆出現，先修正方法與交接規則。不得靠無限重試消耗 token。

優先保留已驗證的格局、尺寸、樓梯、動線與操作。局部外觀問題先局部修；只有基礎架構確實阻礙目標時才重建。

## 跨渲染器驗收
Blender 的光線、程序材質與渲染效果不保證原樣進入 glTF／Three.js。
逐項檢查：UV、貼圖與色彩空間、法線、粗糙度、金屬度、透明與背面、曝光與色調映射、環境光、陰影、材質擴充與支援程度。
需要時烘焙成目標平台可用的貼圖／光照；以最終渲染器截圖證明效果。近景輪廓與視差需要幾何，遠景及微小細節可用貼圖；不能只為省 token 犧牲必要的立體感。

## 看圖檢查
- 光影：亮部保留細節、暗部保留材質，家具接地與桌底有合理陰影；不靠壓黑或泛白掩蓋缺陷。
- 材質：布、石、木、陶瓷、金屬在正常視距能辨認；紋理尺度與粗糙度合理。
- 構造：倒角、接縫、框架厚度與收邊符合尺度。
- 空間：前中後景清楚，窗外不只是一塊無深度色板。
- 構圖：主體完整、視野自然，手機不被地面或操作 UI 佔據。
- 操作與效能：實測移動、轉向、載入、觸控和幀率；不得由模型三角形數推定手機流暢。

住宅可保持明亮；目標是形體、材質與空間層次，不是模仿科幻暗色調。
